## API công khai thêm vào

```rust
pub fn parse(bytes: &[u8]) -> Result<Envelope, EnvelopeError>

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct EnvelopeError { pub field: String, pub message: String }
impl Display for EnvelopeError   // "{field}: {message}", hoặc chỉ message khi field rỗng
impl std::error::Error for EnvelopeError

pub enum Body {
    Notification(Option<NotificationBody>),   // có sẵn
    Vocab(VocabBody),                          // mới
    Generic(GenericBody),                      // mới
}
// Body::kind() trả thêm "vocab" và "generic".

pub struct VocabBody {
    pub word: String, pub ipa: String, pub pos: String,
    pub audio_url: Option<String>, pub meanings: Vec<Meaning>,
    pub context: Option<String>, pub synonyms: Vec<String>, pub antonyms: Vec<String>,
}
pub struct Meaning { pub definition: String, pub examples: Vec<String> }

pub struct GenericBody { pub blocks: Vec<Block> }
pub enum Block {            // gắn thẻ nội bộ theo "type", snake_case
    Heading { text: String },
    Text { markdown: String },
    Fields { items: Vec<Field> },
    List { items: Vec<String>, ordered: bool },        // ordered mặc định false
    Image { url: String, alt: Option<String> },
    Code { text: String, language: Option<String> },
    Link { label: String, url: String },
}
pub struct Field { pub label: String, pub value: String }
```

Các kiểu mới đều derive `Debug, Clone, PartialEq, Eq, Serialize, Deserialize`. Trường `Option` được ghi ra là `null` (không bỏ qua), giống các trường `url`, `ttl` của envelope, để ví dụ §3.2 (có `"audio_url": null`) round-trip không đổi.

## Quyết định nhỏ trong phạm vi

- **Đường dẫn có đoạn không xác định.** Với JSON hỏng `{`, `serde_path_to_error` trả đường dẫn `?`. `parse` dựng `field` từ các đoạn của đường dẫn và dừng ở đoạn không xác định, nên lỗi trỏ tới cha gần nhất đã biết (ở đây là gốc, `field == ""`).
- **`vocab`/`generic` thiếu `body`** (vắng hoặc `null`): `field == ""`, `message == "missing field \`body\`"`, theo cùng quy ước thiếu trường của serde.
- **Rỗng hay trắng.** `source`, `title`, `summary` bị từ chối khi chỉ có khoảng trắng (đúng plan). `word` và `definition` cũng kiểm sau khi bỏ khoảng trắng vì đó là chữ hiển thị. `dedupe_key` chỉ bị từ chối khi đúng là chuỗi rỗng, vì nó là khoá mờ và plan chỉ nói "không rỗng".
- **Kiểm tiền tố URL phân biệt hoa thường** (`HTTPS://` bị từ chối). An toàn hơn và đúng nghĩa "bắt đầu bằng" trong plan.
- `Envelope` vẫn giữ `Deserialize` nhưng không áp luật ngữ nghĩa; doc của crate giờ nói `parse` là bước validate. Worker hiện vẫn gọi `serde_json::from_slice::<Envelope>`; Phase 3 sẽ chuyển sang `envelope::parse`.
